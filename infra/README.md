# Feedback service infrastructure

Terraform for everything behind the feedback form, deployed by
[`.github/workflows/feedback-service.yml`](../.github/workflows/feedback-service.yml).
That workflow runs on every push to `main` that touches `feedback-service/`, `infra/` or the workflow itself, and it can also be started by hand from the Actions tab.

## What it creates

| Piece | Details |
|---|---|
| Network | A VPC with two private subnets. There is no internet gateway or NAT, so nothing inside can reach the internet. |
| Database | RDS PostgreSQL 17 on `db.t4g.micro`. It is private and encrypted, with 7 days of backups and deletion protection. |
| Lambdas (Node 22, arm64) | `…-submit` sits behind a public Function URL, with CORS limited to the site.<br>`…-digest` sends the nightly email.<br>`…-migrate` applies `schema.sql` during each deploy. |
| Email | An SNS topic with your address subscribed, reached from the VPC through an SNS interface endpoint. |
| Schedule | EventBridge Scheduler runs the digest at the time and zone set in `feedback-service/config.json`. |
| Logs | CloudWatch log groups kept for 90 days. |

Terraform state is kept in an S3 bucket named `india-borders-tfstate-<account>-<region>`. The workflow creates the bucket on its first run (private and versioned), and the state inside is encrypted.

Rough cost: about **$21 a month**, made up of:
- database: about $12
- storage: about $2
- SNS endpoint: about $7
- Lambda, SNS, Scheduler and logs: nothing at this volume

Free-tier credits on a new account may cover this at first.

## One-time setup

1. **Create an IAM user for GitHub** (IAM → Users → Create user, with no console access).
   - Attach these AWS managed policies:
     - `AmazonVPCFullAccess`
     - `AmazonRDSFullAccess`
     - `AWSLambda_FullAccess`
     - `IAMFullAccess`
     - `AmazonSNSFullAccess`
     - `AmazonEventBridgeSchedulerFullAccess`
     - `CloudWatchLogsFullAccess`
     - `AmazonS3FullAccess`
   - Then create an **access key** for it (use case: *Third-party service*).
2. **Add these to the GitHub repository** (Settings → Secrets and variables → Actions):

   | Name | Where | Value |
   |---|---|---|
   | `AWS_ACCESS_KEY_ID` | Secrets | the access key ID |
   | `AWS_SECRET_ACCESS_KEY` | Secrets | the secret access key |
   | `FEEDBACK_NOTIFY_EMAIL` | Secrets | where the nightly digest goes |
   | `AWS_REGION` | **Variables** tab | e.g. `us-east-1` |

   The database password is generated by Terraform and never needs to be entered.
3. **Run the workflow.** Go to Actions → *Feedback service* → *Run workflow*. The first run takes about 15 minutes, most of it creating the database.
4. **Confirm the subscription.** AWS emails the `FEEDBACK_NOTIFY_EMAIL` address a link. No digest arrives until it is clicked.
5. **Connect the site.** Copy the *Submit URL* from the run's summary page into `config.js` → `feedbackEndpoint`, then commit and push. This is needed only once, because later deploys keep the same URL.

To check it works, submit feedback on the site, then run `…-digest` from the Lambda console's Test tab. You should get one email, and the row is marked sent.

## Everyday changes

These are all deployed by pushing to `main`:

- **Handler code:** `feedback-service/*.mjs`.
- **Schema:** `schema.sql` must stay idempotent. The migrate Lambda re-runs it whenever it changes.
- **Digest time:** `config.json` → `digest`. The schedule follows it.
- **Anything in `infra/`.**

Pull requests run the tests only: the service tests against a real PostgreSQL, and `terraform test` against a mocked AWS. They never deploy.

## Notes

- **Rate limit:** the submit Lambda is capped at 2 concurrent requests. On a new account whose total Lambda concurrency is only 10, AWS doesn't allow any reservation, so the workflow deploys without the cap and prints a warning. To get the cap, ask AWS Support for a higher concurrency quota.
- **Removing it all:**
  1. Set `deletion_protection = false` in `database.tf`, push, and let it apply.
  2. Run `terraform destroy` with the same backend settings.

  A final database snapshot, `india-borders-feedback-final`, is kept.
- **Safer credentials:** GitHub's OIDC login to an IAM role would remove the long-lived access key. Only the credentials step of the workflow would change.
